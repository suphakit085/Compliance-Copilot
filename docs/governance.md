# การกำกับดูแลข้อมูลและเอกสาร (Data & Document Governance)

ระบบตอบได้ดีเท่ากับเอกสารที่อยู่ในคลังเท่านั้น เอกสารนี้ระบุว่าใครรับผิดชอบอะไร และระบบช่วยบังคับใช้ตรงไหน
เนื้อหาในหัวข้อ "ต้องตัดสินใจโดยคน" คือสิ่งที่ระบบทำแทนไม่ได้

## 1. บทบาทและความรับผิดชอบ

| บทบาท | ความรับผิดชอบ | ระบบช่วยอย่างไร |
|---|---|---|
| **เจ้าของนโยบาย** (หน่วยงานที่ระบุใน `owner`) | ความถูกต้องและทันสมัยของนโยบาย, ทบทวนตามรอบ | เตือนก่อนครบกำหนดทบทวน 30 วัน และแสดงสถานะ "เกินกำหนด" ในหน้า "คลังเอกสาร" |
| **ผู้อนุมัติ** (`approved_by`) | อนุมัติก่อนเข้าระบบ ระบุวันที่อนุมัติ | ไฟล์ที่ไม่มีผู้อนุมัติ/วันที่ถูกปฏิเสธ (`copilot add-policy`) |
| **ทีม Compliance (ผู้ดูแลคลังกฎหมาย)** | เพิ่ม/ตรวจฉบับแก้ไขของกฎหมายและประกาศ, ดูแลอภิธานศัพท์ | `copilot check-updates` เทียบไฟล์กับต้นฉบับ, อภิธานศัพท์ทุกคำต้องระบุเอกสารปลายทาง (`source`) |
| **DPO** | อายุการเก็บประวัติแชต, การส่งข้อมูลให้ผู้ให้บริการ LLM, สิทธิ์เจ้าของข้อมูล | `COPILOT_CHAT_RETENTION_DAYS`, ปุ่มลบประวัติ, การปิดบัง PII ก่อนส่งให้ LLM |
| **ฝ่ายกฎหมาย** | ตรวจข้อความปฏิเสธความรับผิด (disclaimer) และข้อความที่ระบบแสดง | ข้อความอยู่จุดเดียว: `generation/prompts.py` และท้ายหน้าแชต |
| **ผู้ตรวจสอบภายใน** | ตรวจ audit trail | `GET /audit/verify` ตรวจ hash chain |
| **ผู้ดูแลระบบ (IT)** | สิทธิ์ผ่าน SSO group, การสำรองข้อมูล | map group → สิทธิ์ใน `config/sso.yaml` |

## 2. การนำนโยบายภายในเข้าระบบ

1. เขียนตามแม่แบบ [`policy-template.md`](policy-template.md) — ทุกข้อขึ้นต้น "ข้อ N" เพื่อให้อ้างอิงได้ระดับข้อ
2. กรอกส่วน governance: `owner`, `approved_by`, `approved_on`, `review_due`, `status`
3. ตรวจก่อนเข้าระบบ: `uv run copilot add-policy path/to/pol-xxx.md --dry-run`
   (แสดงจำนวนข้อที่ระบบอ่านได้ และเตือนถ้ามีข้อที่ถูกข้าม เช่น ข้อความสั้นเกินไปหรือเลขข้อไม่ต่อเนื่อง)
4. เพิ่มจริง: `uv run copilot add-policy path/to/pol-xxx.md`
5. **นโยบายฉบับใหม่ต้องใช้ `id` ใหม่** และระบุ `supersedes` ฉบับเดิม ส่วนฉบับเดิมให้ใส่ `effective_to`
   (ไม่ลบทิ้ง เพื่อให้ถามย้อนหลัง "ณ วันที่" ได้) — `--replace` ใช้แก้ไขข้อผิดพลาดของฉบับเดียวกันเท่านั้น

| `status` | ผล |
|---|---|
| `draft` | ไม่ถูกทำดัชนี ค้นหาไม่เจอ |
| `approved` | ค้นหาและอ้างอิงได้ |
| `withdrawn` | ถูกถอนออกจากดัชนีทันทีที่รัน `copilot ingest` |

เอกสารที่ `synthetic: true` เป็นข้อมูลจำลองสำหรับสาธิต ระบบแสดงป้ายกำกับและ `copilot governance` จะเตือนจนกว่าจะแทนที่ด้วยของจริง
**ก่อนใช้จริง: ลบ `data/internal/*.md` ตัวอย่างทั้ง 6 ฉบับ แล้วเพิ่มนโยบายที่อนุมัติแล้วของธนาคาร**
นโยบายที่จัดชั้นความลับสูงให้ระบุ `classification` และ `departments` ให้ตรงกับผู้ที่ควรเห็น —
สิทธิ์ถูกบังคับทั้งใน SQL และ Row-Level Security

## 3. คลังกฎหมายและประกาศ

- รายการอยู่ใน `data/sources.yaml` (ลิงก์ดาวน์โหลด, เลขอ้างอิงทางการ, วันที่มีผล, ฉบับแก้ไข `amended_by`)
- ไฟล์ทุกฉบับถูกตรึงด้วย SHA-256 ใน `data/raw/manifest.lock.json`
- **ตรวจอัปเดตเป็นรอบ:** `uv run copilot check-updates` ดาวน์โหลดไฟล์เทียบในหน่วยความจำ ไม่เขียนทับของเดิม
  และคืนค่า exit code 1 ถ้ามีฉบับที่เปลี่ยน (ตั้งใน cron/CI รายสัปดาห์ได้)
  - `changed` → คนต้องอ่านฉบับใหม่ก่อน แล้วจึง `copilot fetch --force` และ `copilot ingest`
    (ระบบเก็บทั้งฉบับเดิมและใหม่ไม่ได้ในไฟล์เดียว ให้เพิ่มเป็นเอกสารใหม่พร้อม `supersedes` ถ้าต้องตอบย้อนหลัง)
  - `unreachable` → ต้นทางบล็อกหรือล่ม ไม่ใช่ว่าไม่เปลี่ยน
  - ผลที่ตรวจสำเร็จถูกบันทึก (`checked_at`) และแสดงในหน้าคลังเอกสาร ถ้าเกิน 90 วันโดยไม่ได้ตรวจ `copilot governance` จะเตือน
- **สิ่งที่ระบบตรวจให้ไม่ได้:** กฎหมายฉบับใหม่ที่ยังไม่อยู่ในรายการ — ต้องมีคนเฝ้าเว็บ ธปท./ก.ล.ต./ปปง./ราชกิจจาฯ
  แล้วเพิ่มเข้า `sources.yaml` (ดู `official_ref` ของฉบับเดิมเป็นตัวอย่าง)

### ขอบเขตคลังปัจจุบัน และสิ่งที่ยังไม่มี

มี 8 ฉบับ (PDPA, ประกาศแจ้งเหตุละเมิด, พ.ร.บ.ฟอกเงิน, กฎกระทรวง CDD, ธปท. สินเชื่ออย่างรับผิดชอบ,
Joint Policy Statement ธปท.–ปปง., ประกาศ ทธ. 35/2556, หนังสือเวียน ก.ล.ต. 50/2568)
**ยังไม่มี** เช่น พ.ร.บ.หลักทรัพย์และตลาดหลักทรัพย์ พ.ศ. 2535, พ.ร.บ.สถาบันการเงิน, ประกาศ ธปท. ด้านไซเบอร์/Outsourcing,
ประกาศ ก.ล.ต. ด้านการรู้จักลูกค้า — คำถามในหัวข้อเหล่านี้ระบบจะตอบว่าไม่พบหลักฐาน ซึ่งเป็นพฤติกรรมที่ถูกต้อง
แต่ทีม Compliance ควรตัดสินใจว่าฉบับใดจำเป็นสำหรับธุรกิจของตน

## 4. อภิธานศัพท์ (`data/glossary.yaml`)

- เจ้าของ: ทีม Compliance; แต่ละคำต้องมี `source` (id เอกสารปลายทาง) ซึ่งมีเทสต์ตรวจ
- เพิ่มคำใหม่เมื่อ evaluation หรือ feedback 👎 แสดงว่าคนถามด้วยคำที่กฎหมายไม่ใช้
- **หลังเพิ่มคำใหม่ ต้องวัดผลด้วยชุดคำถามที่ไม่เคยเห็น** (ดู README หัวข้อ held-out) เพราะคำที่เพิ่มหลังเห็นผล eval จะทำให้ตัวเลขสูงเกินจริง

## 5. ต้องตัดสินใจโดยคน (ระบบทำแทนไม่ได้)

- [ ] ผู้ให้บริการ LLM ที่ได้รับอนุมัติ และสัญญา zero-retention / data residency
- [ ] ระยะเวลาเก็บประวัติแชต (`COPILOT_CHAT_RETENTION_DAYS`) และ audit log
- [ ] ข้อความปฏิเสธความรับผิดที่ฝ่ายกฎหมายรับรอง
- [ ] รายชื่อเจ้าของนโยบายและผู้อนุมัติของแต่ละฉบับ
- [ ] การจัดชั้นความลับ/แผนกของนโยบายแต่ละฉบับ
- [ ] ผู้รับผิดชอบเมื่อคำตอบผิด: ใครรับเรื่อง ใครแก้เอกสาร/อภิธานศัพท์ ใครแจ้งผู้ใช้ — แนะนำให้ใช้ปุ่ม 👎 + audit id เป็นจุดเริ่มต้นเรื่อง
- [ ] ความถี่ของ `check-updates` และผู้รับแจ้งเตือนเมื่อพบฉบับเปลี่ยน
