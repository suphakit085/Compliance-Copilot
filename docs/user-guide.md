# คู่มือผู้ใช้และแผนอบรม

เอกสารนี้ใช้ได้สองแบบ: อ่านเองเพื่อใช้งาน และใช้เป็นแผนอบรมผู้ใช้กลุ่มนำร่อง เนื้อหาย่อเดียวกันอยู่ในแอปที่เมนู "คู่มือ"
ข้อตกลงการใช้งานที่ผู้ใช้ต้องยอมรับคือ [`config/terms.th.md`](../config/terms.th.md) (ฉบับเดียวกับที่แสดงในแอป)

## 1. สิ่งที่ต้องเข้าใจก่อนเริ่ม (ครึ่งหน้า)

| ระบบทำได้ | ระบบทำไม่ได้ |
|---|---|
| ค้นกฎหมาย ประกาศ และนโยบายภายในที่คุณมีสิทธิ์เห็น แล้วสรุปพร้อมอ้างอิงถึงมาตรา/ข้อ | ให้ความเห็นทางกฎหมายหรือตัดสินแทนผู้มีอำนาจ |
| ตอบตามฉบับที่มีผลบังคับ ณ วันที่เลือก | รู้กฎหมายที่ไม่อยู่ในคลัง (ระบบจะบอกว่า "ไม่พบหลักฐาน") |
| ชี้ให้เห็นเมื่อนโยบายภายในขัดกับกฎหมาย (ผู้ใช้กลุ่ม Compliance) | รับประกันว่าตีความถูกทุกครั้ง — ตรวจได้เพียงว่าข้อความที่อ้างมีอยู่ในต้นฉบับจริง |

**กฎข้อเดียวที่สำคัญที่สุด:** ถ้าเรื่องนั้นมีผลต่อลูกค้า การรายงานหน่วยงานกำกับ หรือความรับผิดของธนาคาร
ให้เปิดต้นฉบับที่อ้างอิงอ่านเองและให้ผู้มีอำนาจยืนยัน อย่าใช้คำตอบของระบบเพียงอย่างเดียว

## 2. วิธีอ่านผลลัพธ์

| สิ่งที่เห็น | หมายความว่า | ทำอะไร |
|---|---|---|
| ป้ายเขียว "ตอบจากแหล่งอ้างอิงที่ตรวจสอบแล้ว" | ข้อความที่อ้างทุกประโยคพบในต้นฉบับ | กดป้าย [S1] อ่านต้นฉบับก่อนใช้ |
| ป้ายเหลือง "ตอบได้บางส่วน" | หลักฐานครอบคลุมบางส่วนของคำถาม | อ่านส่วนที่ขาดจากต้นฉบับหรือถามฝ่ายกำกับ |
| ป้ายแดง "ยืนยันแหล่งอ้างอิงไม่ได้" | ข้อความที่โมเดลอ้างไม่ตรงต้นฉบับ ระบบแสดงต้นฉบับแทน | **ห้ามใช้คำตอบ** อ่านต้นฉบับเอง และกดรายงานปัญหา |
| "ไม่พบหลักฐานเพียงพอ" | ไม่มีหลักฐานในเอกสารที่คุณมีสิทธิ์เห็น | ไม่ได้แปลว่ากฎหมายไม่มี — ปรับคำถามหรือถามฝ่ายกำกับ |
| "แสดงข้อความต้นฉบับ (ไม่มีคำตอบจาก AI)" | ระบบสร้างคำตอบไม่ได้ในตอนนี้ (เช่น โควตา) | อ่านข้อความต้นฉบับที่แสดง |
| ข้อความ "ร่างคำตอบ — ยังไม่ได้ตรวจสอบ" ขณะพิมพ์ | ตัวอย่างที่ทยอยแสดง ยังไม่ผ่านการตรวจอ้างอิง | รอจนมีป้ายสถานะ อย่านำไปใช้ |
| ป้ายเหลือง "ปิดบังข้อมูลส่วนบุคคล" | ระบบตรวจพบและปิดบังข้อมูลส่วนบุคคลในคำถามก่อนส่ง AI | ครั้งหน้าไม่ต้องใส่ข้อมูลลูกค้า |
| คำเตือนสีส้ม (ฉบับแก้ไข/เอกสารตัวอย่าง) | มีฉบับแก้ไขที่ยังไม่รวม หรือเอกสารเป็นข้อมูลจำลอง | อ่านคำเตือนก่อนใช้คำตอบ |

## 3. ถามให้ได้คำตอบดี

- ใส่สถานการณ์จริงและตัวเลข: "ลูกค้าส่งกระเช้ามูลค่า 4,000 บาท ผมกำลังพิจารณาสินเชื่อให้เขา รับได้ไหม"
- ระบุกฎหมาย/มาตราถ้ารู้: "PDPA มาตรา 30 ต้องดำเนินการภายในกี่วัน"
- ถามย้อนหลัง → เลือก "ตามกฎ ณ วันที่" ให้ตรงวันเกิดเหตุ
- ไม่ต้องใส่ชื่อ เลขบัตร เบอร์โทร เลขบัญชีของลูกค้า
- ถามต่อเนื่องได้ ระบบจำบริบทของบทสนทนา; เริ่มเรื่องใหม่ให้กด "แชทใหม่"

## 4. เมื่อพบปัญหา

กด 👎 ใต้คำตอบ เลือกประเภท (คำตอบไม่ถูกต้อง / อ้างอิงไม่ตรง / ใช้ฉบับเก่า / ควรตอบได้แต่ปฏิเสธ / **เห็นข้อมูลที่ไม่ควรเห็น** / อื่น ๆ)
และเขียนสั้น ๆ ผลการแก้ไขจะแสดงที่เมนู "คู่มือ" หัวข้อ "เรื่องที่ฉันรายงาน" กระบวนการหลังจากนั้น: [incident-process.md](incident-process.md)

เห็นเอกสารที่ไม่ควรเห็น → รายงานทันที เป็นเหตุการณ์ด่วน อย่าส่งต่อหรือคัดลอกเนื้อหานั้น

## 5. แผนอบรม (ผู้ใช้กลุ่มนำร่อง 5–10 คน)

| ช่วง | เวลา | เนื้อหา | วิธี |
|---|---|---|---|
| 1. หลักการ | 15 นาที | หัวข้อ 1: ทำอะไรได้/ไม่ได้, ทำไมต้องตรวจต้นฉบับ, ข้อตกลงการใช้งาน | บรรยาย + เปิดข้อตกลงในแอป |
| 2. อ่านผลเป็น | 20 นาที | หัวข้อ 2: ป้ายสถานะ, การกดอ้างอิงเทียบต้นฉบับ | สาธิต 4 คำถาม (ดูตัวอย่างด้านล่าง) |
| 3. ลงมือทำ | 25 นาที | ผู้เรียนถามจากงานจริงของตน อ่านต้นฉบับ และบอกว่าจะใช้คำตอบหรือไม่ | ฝึกเป็นคู่ |
| 4. รายงานปัญหา | 10 นาที | กด 👎 จริง 1 เรื่อง ดูผลที่หน้า "คู่มือ" | ฝึก |
| 5. ทดสอบความเข้าใจ | 10 นาที | แบบทดสอบด้านล่าง ผ่านตั้งแต่ 4 จาก 5 | ข้อเขียนสั้น |

**คำถามสาธิตที่ครอบคลุมพฤติกรรมสำคัญ** (ทำงานกับคลังตัวอย่างปัจจุบัน):

1. "ถ้าข้อมูลลูกค้ารั่วไหล ต้องแจ้งสำนักงานคุ้มครองข้อมูลภายในกี่ชั่วโมง และนโยบายภายในเราสอดคล้องไหม" — ตอบพร้อมอ้างอิง และเห็นว่านโยบาย 7 วัน ขัดกับกฎหมาย 72 ชั่วโมง
2. "พนักงานรับของขวัญตามเทศกาลได้ไม่เกินกี่บาท" แล้วเปลี่ยนวันที่เป็นปี 2024 — คำตอบเปลี่ยนตามฉบับที่มีผล
3. "แนะนำร้านกาแฟแถวสีลม" — ระบบปฏิเสธ ไม่ตอบนอกเรื่อง
4. ล็อกอินเป็นพนักงาน แล้วถามเรื่องคู่มือ STR ของหน่วยงาน AML — ไม่เห็นเนื้อหา; ล็อกอินเป็นเจ้าหน้าที่ Compliance แล้วถามซ้ำ — ตอบได้

**แบบทดสอบความเข้าใจ (เฉลยในวงเล็บ):**

1. ระบบตอบ "ไม่พบหลักฐานเพียงพอ" แปลว่ากฎหมายไม่มีเรื่องนี้ใช่หรือไม่? (ไม่ใช่ แปลว่าไม่มีหลักฐานในเอกสารที่ฉันมีสิทธิ์เห็น)
2. คำตอบมีป้ายแดง "ยืนยันแหล่งอ้างอิงไม่ได้" ควรทำอย่างไร? (ไม่ใช้คำตอบ อ่านต้นฉบับ รายงานปัญหา)
3. เรื่องที่จะรายงานหน่วยงานกำกับ ใช้คำตอบของระบบอย่างเดียวได้หรือไม่? (ไม่ได้ ต้องให้ผู้มีอำนาจยืนยันจากต้นฉบับ)
4. ต้องการทราบกฎที่ใช้เมื่อปีที่แล้ว ทำอย่างไร? (เลือก "ตามกฎ ณ วันที่" เป็นวันเกิดเหตุ)
5. พบเอกสารลับของหน่วยงานอื่นปรากฏในคำตอบ ทำอย่างไร? (รายงานประเภท "เห็นข้อมูลที่ไม่ควรเห็น" ทันที ไม่คัดลอกหรือส่งต่อ)

## 6. แผนนำร่อง (เสนอ ให้ธนาคารปรับตามบริบท)

| | |
|---|---|
| ระยะเวลา | 4–6 สัปดาห์ ผู้ใช้ 5–10 คนจากทีม Compliance และหน่วยงานที่ถามบ่อย |
| ก่อนเริ่ม | ปิดเงื่อนไขใน [model-risk.md](model-risk.md) หัวข้อ 9 (อย่างน้อย: นโยบายจริง, ผู้เชี่ยวชาญตรวจเฉลย, SSO, ข้อตกลงการใช้) และอบรมตามหัวข้อ 5 |
| ทุกสัปดาห์ | ทีมระบบอ่านรายงานปัญหาและมาตรวัด (`copilot feedback-report --open`, หน้า "รายงานปัญหา", Prometheus) |
| เกณฑ์ผ่านเพื่อขยาย | เหตุการณ์ด่วน (เห็นข้อมูลเกินสิทธิ์) = 0; คำตอบที่ยืนยันอ้างอิงไม่ได้ < 5%; รายงานปัญหาประเภท "คำตอบไม่ถูกต้อง" ทุกเรื่องถูกปิดพร้อมสาเหตุ; ผู้ใช้ผ่านแบบทดสอบ; ผลสุ่มตรวจ 30 คำตอบโดยเจ้าหน้าที่ Compliance ตรงกับต้นฉบับตามเกณฑ์ที่กำหนดร่วมกัน |
| หลังนำร่อง | คำถามที่ผู้ใช้ถามจริงและเรื่องที่รายงาน นำเข้าชุดทดสอบ (`feedback-report --draft`) ให้ผู้เชี่ยวชาญยืนยัน แล้ววัดผลซ้ำก่อนขยาย |

เกณฑ์ตัวเลขข้างต้นเป็นข้อเสนอเริ่มต้น ไม่ใช่ข้อกำหนดจากหน่วยงานกำกับ
