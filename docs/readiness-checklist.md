# เช็กลิสต์ความพร้อมใช้งานจริง (สถานะ ณ 1 พ.ย. 2569)

สัญลักษณ์: ✅ ทำและตรวจแล้ว · 🟡 ทำแล้วแต่ยังไม่ยืนยันบางส่วน · ⬜ ต้องให้ธนาคารทำ/ตัดสินใจ (ระบบทำแทนไม่ได้)
รายการสดจากระบบที่รันอยู่ดูได้จาก `copilot evidence-pack` (หัวข้อ "ข้อค้นพบ")

## 1. ก่อนนำเสนอ
- ✅ ชุดคำถามทดสอบ 218 ข้อ (golden 51 / held-out 21 / extended 146) และรายงานผล แยกรอบ blind กับหลังแก้
- ✅ ภาพหน้าจอใน README, สคริปต์วิดีโอเดโม ([demo-script.md](demo-script.md))
- ⬜ อัดวิดีโอสำรอง (คุณต้องอัดเอง ตามบทใน demo-script)
- ✅ ประวัติแชต (แยกจาก audit, ลบได้, ตรวจสิทธิ์ซ้ำเมื่อเปิด)

## 2. ความปลอดภัยและการยืนยันตัวตน ([security.md](security.md))
- ✅ SSO แบบ OIDC (PKCE) ทดสอบกับ Keycloak; สิทธิ์มาจาก group ของ IdP
- ✅ Row-Level Security ชั้นที่สอง; ล็อกบัญชีหลังผิด 5 ครั้ง; rate limit; CSP และ security headers; ตรวจ production ตอนเริ่มระบบ
- ✅ สแกน dependency (Python ไม่พบช่องโหว่; เว็บมี 6 รายการใน toolchain ของ shadcn ที่ไม่รันตอนใช้งาน ยอมรับและบันทึกไว้)
- ⬜ เชื่อม SSO กับ IdP จริงของธนาคาร (ชื่อ claim ของ group, single logout, token refresh)
- ⬜ ทดสอบเจาะระบบโดยทีมความปลอดภัย; จัดการความลับด้วยระบบของบริษัท; TLS ที่ reverse proxy
- ⬜ ย้าย rate limit ไป gateway/Redis หากมีหลาย replica

## 3. ข้อมูลและกฎหมาย ([governance.md](governance.md))
- ✅ กลไกรับนโยบาย (เจ้าของ ผู้อนุมัติ วันทบทวน สถานะ), `add-policy`, `check-updates`, แม่แบบนโยบาย
- ⬜ **แทนนโยบายตัวอย่าง 6 ฉบับด้วยนโยบายจริงที่อนุมัติแล้ว**
- ⬜ เลือกกฎหมายที่ต้องเพิ่มตามธุรกิจ (เช่น พ.ร.บ.หลักทรัพย์ฯ, ประกาศ ธปท. ด้านไซเบอร์) — ต้องดาวน์โหลดไฟล์ใหม่ ผมยังไม่ได้ทำ
- ⬜ กำหนดเจ้าของอภิธานศัพท์ ผู้เฝ้ากฎหมายใหม่ และความถี่ของ `check-updates`

## 4. LLM และต้นทุน ([security.md](security.md))
- ✅ Streaming (ร่างคำตอบที่ระบุว่ายังไม่ตรวจ แล้วแทนด้วยคำตอบที่ตรวจแล้ว), เริ่มสร้างใหม่เมื่อ stream ถูกตัด, ถอยไปแสดงต้นฉบับเมื่อโควตาหมด
- 🟡 ตอนนี้ใช้ `gemini-3.1-flash-lite` (แผนฟรีมีโควตาจำกัด); กลไกเริ่มสร้างใหม่ทดสอบด้วยเทสต์ ยังไม่เคยเจอ 503 จริงหลังแก้
- ⬜ เลือกผู้ให้บริการ/ภูมิภาค สัญญา zero-retention แผนชำระเงิน และตัดสินว่าจะส่งเอกสารชั้นลับให้ผู้ให้บริการภายนอกหรือไม่ (ทางเลือก: โมเดลในองค์กร)

## 5. คุณภาพ ([evaluation.md](evaluation.md))
- ✅ ขั้นตอนให้ผู้เชี่ยวชาญตรวจเฉลย (Excel + ledger + `--reviewed-only`), วงจร 👎 → ร่างคำถาม, Gap Analysis อ่านกฎหมายแม่คู่กับประกาศลูก
- ⬜ **ผู้เชี่ยวชาญ compliance ยืนยันเฉลย — ตอนนี้ 0 จาก 218 ข้อ**
- ⬜ ขยายชุดคำถามจากคำถามจริงของผู้ใช้; ผู้ตรวจอิสระทบทวนผล
- 🟡 ข้อ 3 ของนโยบาย PDPA ตัวอย่างถูกจัดเป็น conflict ระดับสูงใหม่ — ผู้เชี่ยวชาญควรตัดสินระดับ
- 🟡 ยังไม่ได้วัด end-to-end ของชุด extended กับโมเดล 3.5 Flash (ใช้ 3.1 Flash Lite)

## 6. การ deploy ([deployment.md](deployment.md))
- ✅ Docker (API CPU/CUDA, เว็บ), compose แบบ production ที่รันและทดสอบแล้ว, CI (lint, เทสต์, build), สำรอง/กู้คืนที่ทดสอบจริง, metrics + กฎแจ้งเตือน 12 ข้อ
- ✅ วัดความสามารถรองรับ: GPU 8 GB ~2 คำถาม/วินาทีต่อ process; CPU ช้ากว่า ~20 เท่า
- 🟡 Integration บน GitHub: ขั้น ingest และเทสต์ทั้งชุดผ่าน; quality gate เคยเกินเวลาและปรับแล้ว **ผลรอบล่าสุดยังไม่เห็น**
- 🟡 image แบบ CUDA ยังไม่เคย build
- ⬜ นำ image ขึ้น registry และ rollout ตามกระบวนการของธนาคาร; ผู้รับแจ้งเตือน; ซ้อมกู้คืนบนข้อมูลจริง

## 7. การนำไปใช้ในองค์กร ([model-risk.md](model-risk.md), [user-guide.md](user-guide.md), [incident-process.md](incident-process.md))
- ✅ ข้อตกลงการใช้งาน (บังคับที่เซิร์ฟเวอร์, มีเวอร์ชัน, บันทึกใน audit), รายงานปัญหา → ปิดเรื่อง → ผู้รายงานเห็นผล ทดสอบผ่านหน้าเว็บจริง
- ✅ เอกสารความเสี่ยงโมเดลฉบับร่าง + model card สร้างอัตโนมัติ, คู่มือและแผนอบรม, กระบวนการรับมือเหตุการณ์
- ⬜ ฝ่ายกฎหมายรับรองข้อตกลง; DPO อนุมัติการไหลของข้อมูลและอายุเก็บ
- ⬜ กำหนดผู้รับเรื่องเวรจริง ช่องทางนอกระบบ และเกณฑ์แจ้งหน่วยงานกำกับ
- ⬜ ผู้ตรวจโมเดลอิสระ + คณะกรรมการลงนาม; อบรมกลุ่มนำร่องและกำหนดเกณฑ์ผ่านของธนาคาร

## สิ่งที่ต้องไม่อ้างเกินจริง
ระบบเป็นต้นแบบที่ทำงานครบและทดสอบมาก แต่: นโยบายภายในทั้งหมดเป็นข้อมูลจำลอง, ไม่มีเฉลยที่ผู้เชี่ยวชาญยืนยัน,
ไม่เคยใช้กับผู้ใช้จริง, ไม่ผ่านการทดสอบเจาะระบบหรือการตรวจอิสระ ตัวเลขที่ควรอ้างสำหรับคำถามที่ไม่เคยเห็นคือรอบแรกแบบ blind
(held-out: ค้นพบถูก 94.1%, พฤติกรรมถูก 85.7%; extended: ค้นพบถูก 92.2%, พฤติกรรมถูก 94.5%, ข้อเท็จจริงถูก 91.4%, รั่วไหล 0)
