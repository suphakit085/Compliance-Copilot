# Evaluation: question sets, results and what they do not prove

218 questions in three sets, scored mostly by deterministic checks (evidence strings, key facts,
quote verification), not by an LLM judge. **No question has yet been confirmed by a compliance
expert** - every set was written by the engineers from the source text. That is the main
limitation; the review workflow below exists to close it.

| Set | Questions | Written | Role |
|---|---|---|---|
| `main` (`golden_set.yaml`) | 51 | before tuning | the system was tuned on it - results are optimistic |
| `holdout` (`holdout_set.yaml`) | 21 | after tuning, run once blind | first honest estimate; no longer blind after its defects were fixed |
| `extended` (`eval/extended/*.yaml`) | 146 | after all tuning, run once blind | covers all 14 documents, every category, colloquial phrasing, versions, access control, refusals, injection, personal data |

Every evidence string is machine-checked against the corpus (`tests/test_eval_sets.py`,
`copilot eval` validates the gold first): that caught three quotes broken by PDF line breaks, one
ambiguous quote and, in the first run, one question whose gold evidence was incomplete.

## Results on the extended set (146 questions)

**Retrieval, first run - blind** (before any change in response to this set):

| Configuration | Hit@6 | MRR |
|---|---|---|
| A. Fixed-size chunks + vector only | 0.516 | 0.401 |
| B. Structure-aware chunks + vector only | 0.859 | 0.759 |
| C. Structure-aware chunks + BM25 only | 0.758 | 0.584 |
| D. Hybrid (vector + BM25 + references) | 0.852 | 0.722 |
| E. Hybrid + cross-encoder rerank | 0.938 | 0.829 |
| **F. + glossary + comparison lookup (production)** | **0.922** | **0.810** |

Confidential-document leakage was 0 in every configuration. Note that the production
configuration (F) was *below* E on this set: the glossary expansion for "ข้อมูลรั่ว" pulled PDPA
section 37 above the notification that actually classifies breaches.

The misses were mostly vocabulary gaps (staff say "ขนม", "ติ๊กยินยอม", "ส่งข้อมูลไปธนาคารอื่น"; the
texts say "ของขวัญ", "เงื่อนไขในการให้ความยินยอม", "ส่งหรือโอนข้อมูล") and penalty questions
("โทษ" vs "ต้องระวางโทษปรับ"). Six glossary entries were added for them. **After that fix Hit@6 is
0.977 (MRR 0.857) - but that is not a blind number any more.** The main set stays at 1.000 and the
held-out set at 1.000.

One experiment was rejected: reranking with the *original* question instead of the glossary-expanded
one raised the extended set by 1.5 points but dropped the held-out set from 1.000 to 0.941, so it was
not adopted.

**End to end** (first run on this set, answers generated by `gemini-3.1-flash-lite`, the batch model -
the chat model's daily quota was exhausted):

| Metric | As run | After correcting 3 gold wordings |
|---|---|---|
| Correct behaviour (answer / abstain / block) | **94.5%** | 94.5% |
| Key facts in answers | 91.4% | **93.8%** |
| Cited quotes found verbatim in the source | 95.9% | |
| Citation recall | 92.2% | |
| Confidential-document leakage | **0** | |
| Personal data masked | 100% | |
| Prompt injections blocked / legitimate questions wrongly blocked | 5 of 5 / 0 | |

By category (behaviour): regulation 93.5% (n=93), policy 100% (14), versioning 100% (6), conflict 100%
(4), explicit reference 100% (5), injection 100% (5), personal data 100% (4), unanswerable 100% (5),
out of scope 100% (4), **access control 66.7% (6)**.

What went wrong, all 8 behaviour misses and the fact misses, classified:

- **4 answers with citations that could not be verified** (x-aml-13, x-brc-01, x-pdpa-08,
  x-pdpa-14): the model's quote was not in the source, so the system correctly fell back to showing the
  source text instead of the answer. A real weakness (2.7%), safe in effect.
- **2 answerable questions refused** with "insufficient evidence" (x-pdpa-02, x-pdpa-12).
- **2 access-control "failures"** (x-rbac-01, x-rbac-03): the system answered `partial` - it said the
  specific information is not available to this user and answered from documents the user may read.
  Nothing confidential was disclosed (leakage 0), but the strict metric expects a plain refusal; an
  expert should decide whether `partial` is acceptable.
- **Wrong or incomplete answers**: x-aml-21 promised steps and did not list them; x-pdpa-04 ("what must
  we tell customers when collecting data") was answered from the securities notification instead of
  PDPA section 23.
- **Gold too strict** (corrected, openly): x-pol-07 answered correctly with "regardless of value" where
  the key fact said "every value"; x-aml-25 and x-jps-02 required a second phrase the question did not
  ask for. Only changes that can be verified were applied: the stored answers are cut at 600 characters,
  so a fact may only be credited when it *is* found, never withdrawn (the limit is now 4,000).

Not measured: end-to-end results for the chat model (`gemini-3.5-flash`), and any result on
expert-reviewed questions.

## Expert review

```bash
copilot eval-review status                                  # how much of each set an expert has confirmed
copilot eval-review export --sets extended --out review.xlsx   # workbook for the compliance team
copilot eval-review import review.xlsx --reviewer "ชื่อผู้ตรวจ"  # record ok / fix / reject
copilot eval --set extended --reviewed-only                 # score only expert-confirmed questions
```

The workbook shows, per question, the expected behaviour, the quoted evidence and the facts an answer
must contain, with a dropdown for the verdict. Verdicts go to `eval/review/ledger.yaml`, keyed by a
fingerprint of the question: **editing a question after review makes the review stale** instead of
silently keeping the approval, `reject` removes a question from every metric, and an import with any
invalid row records nothing. Every report states how many of its questions an expert confirmed.

Suggested use: have the compliance team confirm the 146 extended questions first (roughly an afternoon
for two people), then report `--reviewed-only` numbers as the headline.

## Closing the loop with users

```bash
copilot feedback-report --days 30          # thumbs-down answers: what was asked, what the system did
copilot feedback-report --draft <audit id> # writes eval/inbox/fb-<id>.yaml
```

The draft carries the (masked) question and what happened, and leaves `expect`, `evidence` and
`key_facts` empty on purpose: the system's own answer must not become the gold. An expert completes it,
it joins a question set and the review ledger, and the regression is then caught by every future run.

## Policy gap analysis across legal layers

Thai rules are layered - Act, ministerial regulation, regulator notification, circular. Gap analysis
used to retrieve from all of them together without telling the model which was which, and could read a
notification without the Act it implements. Now each document can name its `parent` in
`data/sources.yaml` (4 relations in the corpus); the parent is retrieved alongside whenever only the
child ranked, each source is labelled with its level, and the prompt (`gap-v3`) requires the clause to
meet the strictest requirement and says the higher level prevails when sources differ.

Run on the sample PDPA policy (live, `gemini-3.1-flash-lite`): both planted conflicts were found (access
requests "45 days" vs 30; breach notification "7 days" vs 72 hours, citing the Act *and* the PDPC
notification), plus 4 omissions. It also now flags clause 3 ("sensitive data ... unless another legal
basis applies") as a high-severity conflict with PDPA section 26, whose exceptions are an exhaustive
list. That reading is defensible but the severity may be too strong - a call for the compliance team,
not the tool.

## Limits

- One author, no expert confirmation yet (0 of 218 reviewed); the extended set was fully blind only
  for its first run.
- Question phrasing comes from engineers imagining staff; real query logs and the thumbs-down loop
  are the way to cover real phrasing.
- Deterministic key-fact matching rewards the expected wording: a correct answer in different words
  can fail (three did) and a vague answer containing the words can pass.
- The synthetic internal policies make the policy/versioning/access-control questions easier to
  write than real, messier policies will be.
